# Private Matter Assistant: how the legal build fits together

This is the code map for the legal build spec (Nov 3, 2026). The design is the medical
project's: three agents clean every document offline, search runs on the originals, and the
answering model only sees cleaned text. Set `SANITISE_DOMAIN=legal` (the default) to get the
legal prompts, corpus and client table. The test suite pins `medical` for the older tests.

## Running it

On Kaggle, run `notebooks/legal_kaggle.ipynb` from top to bottom. To run it on a laptop
without a GPU:

```bash
python -m sanitise.legal generate            # data/legal/ (fixed seed, already committed)
python -m sanitise.legal ontology            # data/ontology/
python -m sanitise.legal all --mock          # rules + deterministic rewrite + canned answers
```

With models (`GEMINI_API_KEY` set; on this branch every legal agent runs on Gemini, so the
original documents go to Google: fictional data only):

```bash
python -m sanitise.legal build               # resumes after a restart
python -m sanitise.legal evaluate
python -m sanitise.legal report              # data/legal/results/REPORT.md + charts/
python -m sanitise.legal export              # data/legal/bundle/ for the dashboard
```

`--limit N` builds only the first N documents. `--mi-limit N` shrinks the membership probes
if Gemini rate limits bite (the spec's fallback is 100 + 100).

## Domains and models

Every domain runs the same pipeline. `config/domains.json` gives each domain its prompts,
data and models (legal on this branch: Gemini for the agents and the answers). The dashboard's
domain dropdown, `?domain=` on any API call, or `X-Sanitise-Domain` switches a request to that
domain. Kaggle steps, checking each agent, and Gemini key rotation:
[kaggle_steps.md](kaggle_steps.md); for this branch's notebook,
[kaggle_steps_gemini.md](kaggle_steps_gemini.md).

| Setting | Default | Purpose |
|---|---|---|
| `SANITISE_DOMAIN` | `legal` | domain for requests that do not choose one |
| `SANITISE_DOMAINS_FILE` | `config/domains.json` | models and data per domain |
| `GEMINI_API_KEY`, `_2` ... `_9` (environment or Kaggle secrets) or `SANITISE_GEMINI_API_KEYS` (.env) | unset | keys, rotated on limits |
| `SANITISE_GEMINI_DAILY_TOKEN_BUDGET` | `0` | tokens per key per day; 0 = no budget |
| `SANITISE_REPLAY_DIR` | unset | serve an exported run in the dashboard |

## What a mock run shows, and what it does not

`all --mock` checks the whole path (300 documents, every attack, every metric) in about a
minute. The rule pass scores P 1.00 / R 1.00 against the generated gold, and with the monitor
off the protected pipeline still never identifies a target, while the baseline identifies
each direct and linkage target in round 1. The canned answer model only quotes the first
record, so QA accuracy, Agent 2 coverage and membership inference are meaningful only from a
real run.
