# Finance domain: the one-day plan

Three people, one day, no meetings: WhatsApp only, to say something is done. Everything people
would normally agree in a meeting is fixed here. Each person works in their own folders, so
nobody waits on anyone and nobody overwrites anyone.

Everyone works on the branch **`finance`**. Pull before you start, and before every push.

## The four sources

Finance has three use cases plus handwritten cheques. Every source is external: real, or
synthetic but published and labelled by someone else. Nothing is generated by us, except as a
fallback for the bank population (see Person A).

| # | Use case | Data | Real? | Metrics it gives |
|---|---|---|---|---|
| 1 | **Bank customers** | [CFPB complaints](https://files.consumerfinance.gov/ccdb/complaints.csv.zip) (Hugging Face mirror `CFPB/consumer-finance-complaints`) + [AgamiAI Indian bank statements](https://huggingface.co/datasets/AgamiAI/Indian-Bank-Statements) | real text (CFPB masks names as "XXXX") + external synthetic PDFs with JSON | single-question; the statement holders are the **population for the multi-question attacks** |
| 2 | **Loan / KYC** | [Gretel synthetic PII finance](https://huggingface.co/datasets/gretelai/synthetic_pii_finance_multilingual) + [NIST SD2 tax forms](https://www.nist.gov/srd/nist-special-database-2) | external synthetic, labelled by the makers | Target Info against the dataset's labels, Agent 1 precision/recall, end to end on forms |
| 3 | **Corporate finance** | Enron emails (`corbt/enron-emails`) + [TAT-DQA](https://huggingface.co/datasets/next-tat/TAT-DQA) + Kleister-Charity | real | Target Info on real people (Enron), utility on real financial questions (TAT-DQA), end to end on reports |
| 4 | **Handwritten cheques** | [IDRBT cheque images](https://www.idrbt.ac.in/idrbt-cheque-image-dataset/) (112 real cheques, 300 dpi) | real | end to end: handwriting OCR |

## What is already built (the skeleton)

* **`src/sanitise_finance/`**: the healthcare pipeline copied as a starting point
  (`tools/finance/copy_pipeline.py`). It runs as is. Person B tunes it.
  * The person table accepts a population without age or job, and adds `bank`, `branch`,
    `account_type` and `account_number`.
  * An account number counts as a direct identifier, like a name or phone.
* **`tools/eval_suite`** knows finance: `run.py ... --domain finance --source bank|kyc|corporate|cheques`.
  * Each source runs only the metrics it has, and steps it doesn't have are skipped.
  * Target Info is scored against the dataset's own labels.
  * Scans are labelled by the dataset's fields, so no model writes the labels.
  * For scans without a transcription (cheques), OCR is scored by how many field values it read.
* **`tools/finance/common.py`**: `Folder` writes a source's folder in the agreed format. Use it.
* **`tools/finance/<source>.py`**: a starter fetcher per source: the links, what to write, and
  TODOs for you.
* **`tools/finance/make_samples.py`**: a few made-up samples per source, so everything runs
  before the fetchers do. Your fetcher's `f.reset()` removes them.
* **`notebooks/eval_finance_kaggle.ipynb`**: one notebook for all sources; set `SOURCE` in
  cell 1.
* A **"2h" scale**: half of health's 5h volumes, about 2 hours per source.

## Contracts (the format everyone writes)

`data/finance/<source>/`. Every part is optional; write what your source has, with `common.Folder`:

| File | Content | Written by |
|---|---|---|
| `docs/*.json` | `{"doc_id", "text", "source", "private": [values], "meta": {}}`, under 1,900 characters each | `f.doc(text, private=[...])` |
| `heldout/*.json` | the same; documents never indexed (membership inference). Without it, a third of `docs` is held out | `f.doc(text, heldout=True)` |
| `utility.json` | `[{"id", "query", "reference", "doc_id"}]` | `f.utility(question, reference=..., doc_text=...)` |
| `targeted.json` | `[{"id", "query", "values": [...]}]` | `f.targeted(question, values=[...])` |
| `gold.jsonl` + `scans/` | one line per scan: `{"id", "file", "type", "fields": {name: value}, "private": [field names], "questions": [{"question", "answer"}], "text"?}` | `f.scan(bytes, name, type=..., fields=..., private=..., questions=..., text=...)` |
| `population/*.json` (bank) | documents with a `person_id` | `f.doc(text, folder="population", person_id=...)` |
| `data/finance/people.json` (bank) | one row per customer: `person_id, name, town, district, state, bank, branch, account_type, account_number, phone, conditions: [product], doc_ids`. Leave out what the source does not have | `write_people([...])` |

**Rules learned from health and legal:**
* **Utility questions ask about content.** They never name a person, company, account, place or
  date. Ours replaces those, so a question that names them can't be matched and measures
  wording, not usefulness.
* **Labels come from the dataset.** Use Gretel's spans, NIST's answer files, Enron headers,
  TAT-DQA's answers and Kleister's fields. Don't invent values.
* **Don't commit the IDRBT images.** The dataset has no licence. Keep them in a private Kaggle
  dataset. Everything else (text, NIST forms, Kleister pages) can be committed under
  `data/finance/`.
* **No AI or co-author lines in commit messages, and no mention of AI tools in any file.**

**If something goes wrong:**
* **Pipeline v1 late?** A and C run their quick runs anyway. The copied health pipeline
  works, and it tests their data and plumbing.
* **AgamiAI holders don't overlap** (every holder unique in state, bank and product)? Person A
  posts it, then writes a small population (about 100 customers, about 250 documents) only for
  the multi-question metrics, in the same format. Say so in the paper.
* **A run fails partway?** Run the notebook again. Every step resumes from where it stopped.

## Running a test (each person, own Kaggle account)

1. Push your data to `finance`.
2. Kaggle: import `notebooks/eval_finance_kaggle.ipynb` from GitHub (branch **`finance`**).
3. Set up the session:
   * **GPU T4 x2**, **Internet On**;
   * secret **GEMINI_API_KEY** attached (several keys, comma-separated, in that one secret);
   * cheques only: add your IDRBT dataset as an input, and set `CHEQUES_ZIP` to the zip's path.
4. Cell 1: `SOURCE = "<yours>"`, then `SCALE = "quick"` for a check (about 10 minutes, run cell
   by cell), or `SCALE = "2h"` for the real run.
5. Real run: **Save Version → Save & Run All (Commit)**, then close Kaggle.
6. When it finishes, download `eval_results_finance_<source>_2h.zip` from that version's
   **Output** tab.
7. On your laptop:

```bash
git checkout finance && git pull
mkdir -p results/eval/finance
unzip ~/Downloads/eval_results_finance_<source>_2h.zip -d results/eval/finance/
git add results/eval/finance/finance_<source>
git commit -m "Finance results: <source>, 2h scale"
git push
```

8. 📣 Post the key numbers from `REPORT.md`.

**Local check without any model** (mock mode, on a laptop):

```bash
EVAL_MOCK=1 SANITISE_LLM_BACKEND=mock SANITISE_RETRIEVAL_MODE=bm25 \
  python tools/eval_suite/run.py data --domain finance --source bank --work /tmp/fin --scale quick
```

Then run `build`, `single`, `multi`, `e2e-prep`, `e2e` and `report` the same way. Add
`EVAL_DEBUG=1` to see the full error of a failing question.
